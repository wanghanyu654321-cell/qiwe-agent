# Native 隔离验证约定

- 修改网络或进程守卫时，验证TCP的object/位置参数重载、IPv4/IPv6、Unix socket/named pipe、显式listen地址、DNS/UDP及子进程边界。连接仅允许本次fixture实际监听的地址和端口；用实际拒绝反例验证守卫，不能只检查mock函数已安装。
- 启动、模块重载、SQLite重开和独立进程重启分别命名。声称进程重启时，必须由外层启动两个不同进程，第二个只查第一轮持久数据，不重新写入fixture；每轮证据绑定唯一runId及实际执行文件hash，失败不能沿用旧成功证据。
- 源码组合、局部执行和完整宿主恢复分别验收。原collector或外部依赖缺少证据时保留阻塞，不能通过测试端口写safe/ready后宣称真实恢复通过。
- 修改恢复记录的判定或 blocker 条件时，先检索全部 scanner 调用测试及其 fixture，统一检查旧的“全部 blocked／固定四项 blocker”断言。按具体危险对象断言阻塞，保留无监督证据时的全局拒恢复断言；不要只修当前第一个失败再逐轮重跑完整宿主。
- 对共享 IPC 或文件目录注入依赖故障前，先检查其余原调用方。故障应限定到目标依赖的专用路径或协议，验证目标降级且无关输入、输出流程仍可执行；不能破坏共享根目录后把连带失败归因于业务接线。
- 验证 O 队列的实际执行回调前，先初始化本次隔离真实 SQLite；原 runtime-safety marker 读取失败会关闭执行。用有界等待区分“未到达回调”和“回调内目标行为失败”，前者不能作为后者的有效 RED。
- 既有岗位的首轮及重启组合验收前，按原 normalizer 和实际 writer 核对完整策略形状及生成的 env/session 字节协议；不能只依据合成默认配置判定，也不能用宽泛文件允许表修补差异。
