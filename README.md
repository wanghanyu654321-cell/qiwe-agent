# qiwe-agent

企微员工入口接入现有 Agent 与门店业务服务。本仓库当前交付 **T0–T6 本地隔离切片及 T7 受控接入适配**：复用原账号、门店、岗位授权、经营账本和培训服务，验证报数、更正、汇总、Excel，以及任务提交、进度/结果查询、精确取消和重启后查回；补充多成员、Web兼容、授权锁、本地性能、真实SDK发布包离线验证，以及定向Native执行的隔离验证。当前验收与限制见[T7剩余接缝](docs/t7-controlled-acceptance.md)。T7真实联调与发布尚未完成。

## 当前可以验证什么

- 企微成员通过显式服务端绑定关联原账号，不使用管理员 Cookie。
- Web 与企微读取同一份 `WorkbenchAccessStore` 授权；原 Web 管理员开通或撤权后，企微侧同步按当前记录判断。
- 从配置的 Native SQLite 只读查询最小账号状态及本人唯一 Home，不初始化原数据库、不创建岗位、不返回密码字段。
- 检查停用、强制改密、门店/岗位撤权、绑定变更、来源异常、取消与超时；迟到结果不会恢复权限。
- 上下文由本进程工厂登记，复制或伪造的 JSON 不能直接作为执行权限。
- 复用原离线报数解析与SQLite账本，金额使用整数分，保留原期间、快照、新增及更正规则；T2只接收报数、本人确认与单条查询。
- 同一消息重放、重复确认不会重复累计；确认使用已保存的候选项，卡片参数不能修改金额或员工归属。
- 重开数据库或启动新进程后，可用原报告编号查回真实入账状态。确认事务保留原`prepared`通知意图，T3通过显式合成SDK端口验证投递及回执。
- 发送前持久化`attempting`；明确未发送的`blocked`可受控恢复，`unknown/attempting`不盲重发。新查询单独回复，不把原未知通知改成成功。
- 平台事件指纹和回调路由在业务前保留；冲突重放不会先入账再报错。即时确认回复与恢复通知竞争同一条原持久记录，避免双发。
- 本人更正先生成待核对报告，显示旧值和新值；确认后沿用原规则替代原明细，原报告仍可查回。
- 经营汇总保存原版本编号，未知指标保留未知。复用原 Excel 双工作表模板，生成与汇总同版的实际 XLSX，经文件消息回传给当前授权成员。
- 上传成功与文件发送分开记录；上传后再次验权和核对版本，文件发送未知时不自动重投。新请求可显式查询已有历史文件，重复平台事件不会再次上传或发送。
- 任务按当前岗位授权，别名只映射服务端配置的原任务。提交前保存渠道引用；结果未知不自动重跑，取消受理与原运行终态分开记录。
- 培训复用原知识审批、引用校验和持久结果，补充精确取消及迟到输出保护；仅注入合成生成函数，不连接模型。长结果可在企微按页查询。
- 多成员各用独立可信身份入口，共享原账本与工件目录；验证同店经营汇总、跨成员/门店隔离、并发事件去重和文件收件人。群聊仍拒绝访问，不产生业务或发送副作用。
- 原Web开通和业务写入后，企微读取同一报告、更正和文件；关闭合成Web入口、重开存储后继续查回。此项覆盖HTTP开通合同和原业务服务，不代表原Web页面端到端验收。
- 装配仅订阅SDK特定事件；认证成功后逐条建立独立可信上下文，按现有门店/员工映射分发到原服务。掉线、重连、错误、踢线及关闭会废止旧会话，迟到身份结果不能写业务或发新回复；已发生动作仍保存unknown等结果。
- 原Native只读桥按真实导出名称组合任务、工作区、Profile、绑定和run，显式转换字段；沿用原Owner、非Home及精确run校验查回结果。该桥固定关闭执行和取消，不初始化原Native或创建调度器。
- 受控SDK出站适配复用原连接和公开发送方法；同一客户端不复用请求号，取消后不再准入后续帧，迟到ACK不能归给下一条同号消息。已提交的帧仍可能结果未知，保留原持久通知状态。
- 卡片兼容嵌套和原扁平回调；本人确认使用专用更新命令、原任务号和本人接收列表，不能回退为普通stream。缺少单聊归属或群聊继续拒绝。

当前入口限制为 `isolated-synthetic`，发送仍须显式装配并隔离底层I/O。固定的`@wecom/aibot-node-sdk@1.0.7`作为运行依赖供新适配器使用，未升级版本；SDK客户端必须专用于该适配器的业务发送，不允许宿主绕过它发送。**尚未连接真实机器人、发送真实消息或运行原 Agent。** 员工操作和查回使用企微消息/卡片载荷，Web继续承担原管理、数据流转与审计。本地ACK不能视为真实平台受理或手机实收。

## 美容门店场景

已获原`manager`经营岗位授权的美容师发送“今天销售成交88.88元”，系统保存待核对报告并返回期间、金额和确认按钮。本人确认后，原账本记入8888分；再发“查询 报告编号”查回同一条结果。未获该岗位授权的员工不会自动升权。

缺少日期、金额等必要内容时只保留待核对结果，不提供确认按钮。重复消息、已存在的期间冲突、失效卡片及越权请求都有明确处理。销售成交额沿用原口径，不等同收款、充值或余额。

| 员工在企微发送 | 结果 |
| --- | --- |
| `更正 报告编号 1 200元` | 将本人原报告第1条明细改为200元，核对并确认后才替代原金额 |
| `经营汇总 2026-10-18 本月` | 返回当前授权门店汇总及快照编号；另支持半月、四个月、全年 |
| `查询汇总 快照编号` | 查回原版本汇总及当前成员最近文件请求的投递状态，不重发文件 |
| `导出Excel 快照编号` | 原账本版本未变化时生成并回传该版本 Excel；已变化则提示重新汇总 |
| `查询文件 快照编号` | 明确请求取得该版本已存在且校验完整的历史文件；不会静默生成新版 |
| `执行任务 内容营销 weekly` | 按当前岗位授权，触发服务端预先登记的已有任务别名 |
| `培训问答 指导员 家访练习` | 使用原培训服务和获准资料；另支持培训教案，以及执总、总指导视角 |
| `查询任务 岗位 任务编号 [页码]` | 查原任务状态、结果和取消请求；查询不会重新执行 |
| `取消任务 岗位 任务编号` | 核验保存的精确原运行，取消受理后继续查询终态 |

岗位可用原英文键或中文名称：客服接待、前台办理、内容营销、投放辅助、店长经营、评测质检、培训。员工必须已经获得对应岗位授权，命令不能开通权限。

**T5 的 Native 端口目前未连接真实运行时，默认关闭。** 原 Home 会话不能按单条消息指定岗位 Profile，因此只适配已有非 Home 岗位工作区中的原 scheduler 任务；不接受任意提示词直接运行，不创建任务或改 Home 绑定。尚未装配的任务明确拒绝。培训生成也仍由可信装配显式启用合成端口，原 HTTP 暂停/额度门禁保留。

## 本地运行

需要 Node.js 22.13 或更新版本。当前本地验证环境为 Node.js 24.18.0。

```bash
npm ci --ignore-scripts
npm test
npm run typecheck
npm run build
npm run demo
npm run demo:report
npm run demo:delivery
npm run demo:operations
npm run demo:tasks
npm run benchmark:local
```

演示只使用系统临时目录中的合成数据库。`demo`验证开通与撤权；`demo:report`验证报数、确认和新进程查回；`demo:delivery`验证断线恢复和未知结果；`demo:operations`验证250元更正为200元、20%汇总、真实XLSX，以及独立进程查回同版文件和重复事件零重发。不读取本人实际数据库，不连接企微或模型。

`demo:tasks`验证暂停时零触发、Native 合成事实的精确取消、原培训引用结果与迟到输出保护；新进程查回 ready/unknown/取消状态，原事件重复零执行、零发送。它使用本地合成 Native 行投影，不启动原 Agent 或第二个循环。

`benchmark:local`测量4个独立成员入口共享真实临时SQLite/Excel的本地耗时，输出冷首用、热串行及4人并发样本、分段P50/P95、错误与脱敏诊断。SDK和Native仅为合成端口，阶段可能嵌套；这些结果不包含模型、平台网络或手机收取时间，不能作为生产SLA。

## 验证与边界

本切片使用真实临时 SQLite、合成绑定及可控延迟进行验证。`withCurrent()`只串行化原授权库的同步提交，不能保证 Native、绑定与业务多库原子撤权。执行/写入和敏感结果返回前仍须在后续调用方重新核验。

T6跨进程锁测试确认：等待授权事务期间发生撤权或请求过期，受守卫的业务回调不会执行。SQLite同步锁等待本身可能超过请求截止时间，当前预算保证过期后拒绝写入，不是硬响应时限；真实多进程负载与响应容量仍待联调。

T0发现原固定B店与统一开通的账本路径、作用域不同。T2显式注入已有`ManagerStore`、原scope和账号→原员工映射；同一SQLite文件内全局来源去重。真实装配前必须确认原库路径，不能自动切换为空库，也不承诺不同文件间全局去重。本次没有迁移、复制或重建实际经营账本、历史、知识和记忆。

T3在原SQLite文件增加`bot_reply_intents`回复元数据表，记录事件预留、回复计划与投递状态；原`employee_reports`及业务口径保留。主动恢复仅向原成员发送，API `recover`是受控服务端入口，查询不会隐式触发重发；没有新增公网路由、员工重试命令或后台循环。

T4在显式注入的工件目录保存按账号/门店/原scope/员工隔离的快照、XLSX及校验元数据；这是原导出物的适配，不增加业务账本。文件投递复用原回复状态。原快照哈希只覆盖scope、period、entries及rows；跨期附录和观察时间不参与版本编号，同版缓存保留首次观察。Excel沿用原精度边界，极大数受电子表格15位有效数字限制。崩溃留下的导出锁或半文件会拒绝使用，需管理员核实后恢复，不自动覆盖。

T5在显式SQLite文件增加`bot_task_refs`渠道引用元数据，可与原报告文件共用，保存原服务请求键/run及独立取消状态；没有新调度器或Agent循环。培训仍使用原`web:local-training`业务命名空间，目录需按账号/租户/门店/Home分区，不能据此创建或替换Native工作间。取消不回滚已发生的业务副作用；跨进程不持有原培训控制器时只能报告unknown。

T7装配不创建SDK连接、不打开或发现数据库，不持有调用方共享资源的关闭权。每请求使用原T1授权及原Delivery/Tasks/工件服务；默认在途容量8、预算4000ms，溢出明确拒绝。只读Native桥不会将原裸trigger/cancel接到聊天：原trigger还会推进全库任务，实际写入必须保留原进程的依赖、权限和暂停门禁。

SDK已入队回复和分片上传不能随本地预算取消，同req_id迟到ACK也存在归因边界。离线测试已复现这些限制，真实出站仍不准入。卡片事件缺少显式single时继续拒绝；确认回调的实际回复协议和手机效果待真实联调，不把本地stream序列化当成手机卡片更新。
