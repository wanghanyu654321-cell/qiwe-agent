# T2 本地实施约定

日期：2026-10-17。基线：`2590fa5f7dcca42a31ded5daf5ed2dbcc23da643`。

目标：企微单聊文字报数 → 原账本待核对 → 卡片确认 → 查询同一报告。员工无需打开Web。只做本地合成事件及回复载荷，不连接SDK、不发真实消息、不运行模型或修改生产。

1. 原解析器和SQLite账本精选复用；旧XML `source`不变，新渠道使用独立`botSource`。只显式注入一份既有账本及服务端账号/原员工映射，不创建另一套事实源。
2. 沿用T1可信身份及现有`manager`授权，固定租户、门店和账本作用域。未授权的员工不自动升权。消息成员必须匹配T1核实的渠道；确认只采用本人已保存报告的版本和服务端候选项。
3. 授权库锁内执行同步业务，账本锁后及提交前再次检查取消/截止时间。Native、绑定、授权和账本多库不宣称原子撤权；写后敏感结果返回前重新核验。提交成功但回复失败时以原报告查询恢复。
4. 同一文件内来源去重，第一次受理的归属和日期保留；跨店/账号重映射冲突。不同账本文件间的全局路由去重留给受控装配，禁止宣称已覆盖。
5. 复用原确认事务的prepared通知意图，本阶段仅返回官方SDK形状的回复计划，不把它写成已发送或已实收。T3处理真正投递、未知结果和恢复。

验收：有效报数/金额期间、缺项不入账、重复受理及确认、篡改卡片/跨员工/调店/撤权、取消超时、锁等待、重开查回、旧Web/XML回归。先验证失败测试，再实现；全量检查及独立审查后提交。

协议依据：WecomTeam/aibot-node-sdk 1.0.6及已核实的官方源码。仅受理明确`chattype: single`的文字/卡片事件；缺失聊天类型的事件暂拒绝，真实协议样本须在T7核实，不能猜测为私聊。长连接认证仍属T3/T7，不把JSON当平台验真。
