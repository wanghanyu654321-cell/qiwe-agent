# 员工企微接入后续计划

当前交付范围为T0–T6本地隔离切片，以及T7联调前装配（2026-10-20）。报数、更正、汇总、Excel及任务提交/进度查询/精确取消/重启查回已通过本地合成验证，T6补充多成员、Web开通/原业务服务兼容、跨进程授权锁及本地性能验收；T7增加固定真实SDK发布包离线测试、逐事件可信分发、生命周期和原Native只读字段桥。真实机器人和Native任务执行未启用。员工操作和异常查回均在企微完成，Web保留原管理、数据流转和审计职责；原业务与数据不因切换渠道重做。

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| T0 | 核实原事实源、统一授权、Native身份/执行接缝 | 记录真实可用入口与缺口，不编造Hook |
| T1 | 可信成员→原账号→当前门店/岗位→本人Home | 同一授权库、撤权/取消/超时、只读Native、伪造上下文拒绝 |
| T2 | 单聊报数、卡片确认、单报告查回 | 原账本与对象权限，重复消息/确认不重复入账，员工无需Web |
| T3 | 原持久通知意图驱动发送与恢复 | 业务提交与通知分离；attempting/unknown不盲重发 |
| T4 | 更正、汇总和Excel回传 | 同版快照、原口径、指定单聊授权收件人 |
| T5 | 原Agent、岗位、培训任务接缝 | 原会话/运行/工具门禁，进度与取消，不切换活跃Home Profile |
| T6 | 性能、多成员、群保护及Web兼容 | 本地分段P50/P95、权限隔离、同一持久结果、关闭Web仍可查回；群聊继续拒绝 |
| T7 | 受控真实联调与发布准备 | 手机实收、平台限制、有限模型评测、固定制品与回退 |

T7当前仍为前置装配与隔离验收，最新范围及阻塞见[t7-recovery-preparation-acceptance.md](t7-recovery-preparation-acceptance.md)，前轮见[t7-full-host-acceptance.md](t7-full-host-acceptance.md)、[t7-host-readiness-acceptance.md](t7-host-readiness-acceptance.md)。真实联调及发布仍未验收，不能标记整个T7已完成。

按1名熟悉项目开发及关键节点独立审查，T0–T7估算15–20人日，含修复缓冲18–24个有效工作日。平台资格、凭据、模型预算、数据库环境及人工验收等待另计。此估算不是上线日期承诺。

T0–T6没有启用真实SDK连接、原Agent执行或模型。原暂停策略保留；T5只给已有非Home工作区任务配置受控服务端口，不使用管理员Cookie或切换Home Profile。原任意消息入口没有幂等岗位隔离与安全取消接缝，仍未接通；不能把本地合成端口写成已恢复原Agent。

后续兼容扩展要明确机器人来源，不伪造传统XML的CorpID/AgentID。消息第一次受理的业务归属固定，调店后重投不得在新店重新记账。旧记录、XML入口及原网页调用方均须回归。

确认结果与prepared通知意图复用原事务；失败、明确未发送和结果未知分别处理。SDK自动重连、最终帧入队及平台ACK均不能替代持久业务结果或手机验收。

T3复用原delivery与事件预留，T4复用原更正、summary和Excel模板。T5复用原培训业务合同，并以原scheduler的精确run/key语义适配受控任务；渠道引用与消息回复分离，未新增调度循环。T6只新增验收测试和性能脚本，未修改运行源码或依赖；见[t6-acceptance.md](t6-acceptance.md)。

SDK队列取消准入、回执归因、卡片回复及媒体协议已补充受控适配和离线验证；平台受理与手机效果仍待真实联调。Native已增加完整候选宿主启动验证入口，但原恢复清单固定缺少四类证明、所有记录仍为blocked，不能放行。下一步需先为原清单补齐非数据库残留、外部写入者、写入口覆盖和不透明运行元数据的可验证依据，以及启用渠道的真实准备流程；原状态映射和历史执行/通知的关闭证据必须逐项核实，不能直接改safe或绕过prepare。成功恢复、恢复后消费者与在途关停仍不能从分开的定向执行测试推导。

2026-10-21补充候选管理员只读inspect和项目根配置元数据覆盖。核实原渠道connect含补收、同步及卡片回调，会改变review指纹，不能在restore prepare中静默触发；Native IM与企微SDK连接生命周期不同。四类证明、完整队列债务、旧执行者与未知投递的结清依据仍待闭合，本轮没有开放真实渠道或正常恢复。

实际Native写入继续保留原deps/Owner/暂停门禁，不能裸调用会推进全库的trigger。待获得对应授权，再核实真实成员绑定、原库路径/作用域、已有岗位任务及生产Linux环境，开展受控手机联调；本轮不读取真实数据库、凭据或生产运行状态。

真实发送、暂停恢复、模型预算和发布按具体授权推进。手机实收、平台时效/限流、真实并发及模型质量尚未验收。群聊开放和任意对话执行不属于本轮已完成能力；SQLite同步等待的硬时限也未实现。不得为联调删除`isolated-synthetic`限制或将空库当作迁移完成。
