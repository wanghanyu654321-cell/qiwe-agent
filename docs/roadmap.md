# 员工企微接入后续计划

当前交付范围为T0–T4本地隔离切片（2026-10-18）。报数、卡片确认、更正、经营汇总、Excel文件回传/查回和投递恢复已通过本地合成验证，真实机器人连接和投递尚未启用。员工操作和异常查回均在企微完成，Web保留原管理、数据流转和审计职责；原业务与数据不因切换渠道重做。

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| T0 | 核实原事实源、统一授权、Native身份/执行接缝 | 记录真实可用入口与缺口，不编造Hook |
| T1 | 可信成员→原账号→当前门店/岗位→本人Home | 同一授权库、撤权/取消/超时、只读Native、伪造上下文拒绝 |
| T2 | 单聊报数、卡片确认、单报告查回 | 原账本与对象权限，重复消息/确认不重复入账，员工无需Web |
| T3 | 原持久通知意图驱动发送与恢复 | 业务提交与通知分离；attempting/unknown不盲重发 |
| T4 | 更正、汇总和Excel回传 | 同版快照、原口径、指定单聊授权收件人 |
| T5 | 原Agent、岗位、培训任务接缝 | 原会话/运行/工具门禁，进度与取消，不切换活跃Home Profile |
| T6 | 性能、多成员、群聊及Web兼容 | 分段P50/P95、权限隔离、同一持久结果、关闭Web仍可查回 |
| T7 | 受控真实联调与发布准备 | 手机实收、平台限制、有限模型评测、固定制品与回退 |

按1名熟悉项目开发及关键节点独立审查，T0–T7估算15–20人日，含修复缓冲18–24个有效工作日。平台资格、凭据、模型预算、数据库环境及人工验收等待另计。此估算不是上线日期承诺。

T0–T4没有启用真实SDK连接、原Agent执行或模型。Native原消息和取消入口带有原认证/Owner/工具门禁，当前暂停策略也仍生效；T5需要经审查的受控服务端接缝，不能借管理员Cookie绕过。

后续兼容扩展要明确机器人来源，不伪造传统XML的CorpID/AgentID。消息第一次受理的业务归属固定，调店后重投不得在新店重新记账。旧记录、XML入口及原网页调用方均须回归。

确认结果与prepared通知意图复用原事务；失败、明确未发送和结果未知分别处理。SDK自动重连、最终帧入队及平台ACK均不能替代持久业务结果或手机验收。

T3已复用原delivery状态，并在同库增加最小事件预留与回复去重元数据；即时回复和主动恢复共用原确认通知claim。T4复用原更正、summary与Excel模板，并为文件描述符扩展同一回复状态，新增指令和本地工件适配。见[t4-acceptance.md](t4-acceptance.md)。下一步为T5原Agent和岗位任务的受控接缝；真实SDK连接/发送仍需具体授权和后续验收。
