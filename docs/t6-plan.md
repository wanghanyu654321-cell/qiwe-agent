# T6 本地多成员、性能与兼容验收

日期：2026-10-20，UTC+8。基线T5 `ad835dd53590c0f5ebae349eeed5d47aa575f605`；分支`feat/wecom-acceptance-t6`，依赖PR面向T5。基线29文件415项测试通过，原PR1–4仍开放。

目标：按原T6验收已实现链路，发现问题先复现再最小修复。复用现有服务、存储和端口，不重建业务，不启用真实Native/SDK/模型。生产、真实消息、模型额度及main合并均不在本轮范围。

1. **多成员与门店。** 用独立可信成员读取器并发调用同一SQLite事实源与文件目录，验证本人报数/确认/更正/任务、同店经营权限、跨店/租户/账号/绑定隔离、同时导出与固定单聊收件人；同事件竞争不重复入账或执行。测试不使用共享全局当前员工来模拟可信认证。
2. **群聊与失效保护。** 群聊按当前未开放状态检查拒绝和零业务/发送副作用；不能凭T6阶段名开放新权限。验证群卡片、成员伪造、撤权/调店、晚到异步结果及重复路由。
3. **Web兼容与关闭后查回。** 原授权、报数、培训等调用契约做回归；用不监听HTTP的原业务服务写入事实，再经企微查询同一数据；独立进程重开仍可读取原编号。没有原Web路由或浏览器访问依赖时明确记录，不把接口回归写成完整原Web UI验收。
4. **本地性能。** 可重复脚本记录冷/热、串行/并发样本，给出total、可信身份读取、授权/事务、业务/工件及合成SDK阶段P50/P95、样本数/错误数。记录主机环境、配置和数据量。阶段可能嵌套则明确不可求和；模型/真实网络耗时不在样本内，不将合成结果作为生产SLA。
5. **故障与结果可信度。** 重新验证未知执行/通知不重跑、取消不误停其他run、文件一致性和重启查回；对新增复现问题写有效失败测试，再做最小修复，不改运行循环或扩大权限。
6. **交付。** 相关专项、全量test/typecheck/build、原调用方兼容及本地演示，核对最终diff/来源/敏感信息；独立审查固定版本后提交GitHub依赖PR。更新当前roadmap和验收结果，列明T7真实装配、手机实收、性能和模型评测的缺口。

T5保留边界继续有效：Native自由对话仍无安全岗位选择/幂等/精确取消接缝，仅适配已有非Home任务；真实端口默认关闭。培训跨进程缺控制器时不能冒称取消成功。本轮对这些边界做验收，不未经授权恢复生产或模型。
