## 本地密钥与运行方式

真实模型连通脚本需要 Node.js 24，以及本机已有的原 MiniClaw 源码和 Pi SDK 0.84.2。它不是可脱离这些源码独立发布的服务。

本地 `.local/live-model/.env` 使用原配置名：

```dotenv
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
ANTHROPIC_MODEL=deepseek-flash
ANTHROPIC_API_KEY=
MINICLAW_AGENT_RUNTIME=pi
AGENT_RUNTIME=pi
```

在仓库根目录显式运行：

```powershell
node integrations/native/live-model-smoke.ts --live
```

每次仅准入一次指定接口请求，最多 128 个输出 token，关闭自动重试，超时结束子进程。新建临时工作目录，不读取原业务数据；复用原 `sdkQuery` 的无工具会话。为防祖先目录资料进入提示词，连通测试子进程禁用资源发现；这项测试不能作为完整 runner 资源装配的证据。失败只输出固定阶段、错误分类和请求次数，不输出密钥或上游原文。首次启动失败定位为 Windows 无法使用原目录中的 Linux esbuild，已改为 Node 24 原生 TypeScript 加原源码相对导入解析。

企微凭据另存 `.local/live-channel/.env`：`WECOM_BOT_ID`、`WECOM_BOT_SECRET`、`WECOM_CORP_ID`。旧自建应用的 Agent ID/Secret 不能替代智能机器人的 Bot ID/Secret。这些本地文件均被 Git 忽略，填入后也不会自动连接或发送。

## 真实闭环仍需完成

1. 新机器人凭据及实际 SDK 认证已验证；下一步通过指定成员的实际入站事件核实渠道身份。认证成功不能替代成员绑定、岗位授权或业务验收。
2. 复核原 Native 当前账号、门店和岗位资源，并接入其实际授权来源。旧 `unified-cloud-server.mts` 使用本人 Native HTTP 会话、门店 ACL 和已安装岗位清单；2026-10-16 的新 `WorkbenchAccessStore` 只做过隔离验证，未挂入旧部署。因此缺口包含两种授权契约的接线，不能只寻找一个假定已存在的授权库，也不能用合成 grant 替代。新机器人的成员绑定、账号大小写及当前撤权语义仍须核实；员工无需重装已有岗位。
3. 把该真实入口装入同一个受控完整宿主，使用其实际恢复事实、隔离业务数据和受限模型预算。当前新增的是装配 API，尚无可直接启动完整真实试点的命令；不能将离线 fixture 改为联网后称作真实宿主。
4. 指定员工完成自然语言需求、连续追问、精确取消、答案回复及重启查询。分别记录原执行、持久结果、平台 ACK 和手机实收，失败按原状态恢复。
